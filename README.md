# Paymos for WHMCS — accept USDT and USDC for hosting and SaaS billing

WHMCS payment gateway for stablecoin payments. Customer pays the invoice in USDT or USDC on the chain of their choice. Native stablecoin settlement, no auto-conversion.

**Two-minute setup**: the ZIP you download from [paymos.io/dashboard/cms](https://paymos.io/dashboard/cms) ships with your API keys pre-injected, your webhook callback URL pre-built from your WHMCS System URL, and your signing secret pre-registered. No copy-paste, no separate dashboard trip after upload.

## Why this is two minutes, not two hours

Other WHMCS crypto gateways ask you to:
- Create an API key in their dashboard
- Copy the API key + signing secret into WHMCS gateway settings
- Calculate and paste the webhook callback URL yourself
- Configure that URL on their side
- Test the handshake manually

The Paymos package generator does all of that **server-side at download time**:

- Sandbox + Live API credentials — baked into `paymos-config.php` inside the ZIP
- Webhook callback URL — pre-built from the WHMCS System URL you typed in the dashboard
- Signing secret — pre-registered, never shown to you
- Both modes (Sandbox / Live) — pre-wired in one bundle, mode switch lives in WHMCS admin

You upload the files, activate the gateway, switch from Sandbox to Live when ready.

## Install — full walkthrough

### Step 1: Sign in to Paymos (≈30 sec)

1. Go to [paymos.io/login](https://paymos.io/login).
2. Email magic-link **or** Google — no password, no documents.
3. Onboarding wizard, 3 required steps: business name, country, integration pick.
4. Pick **CMS plugin → WHMCS**.
5. You land on [paymos.io/dashboard/quickstart](https://paymos.io/dashboard/quickstart).

### Step 2: Generate the package (≈20 sec)

1. Open [paymos.io/dashboard/cms](https://paymos.io/dashboard/cms).
2. Select **WHMCS**.
3. Confirm the project that should receive WHMCS invoices is selected in your dashboard workspace.
4. Enter your public WHMCS System URL — for example `https://billing.example.com`.
5. Review the project's success and failure URLs (override if WHMCS uses different return pages).
6. Click **Download WHMCS package**.

The ZIP is built server-side at this moment. Paymos creates or reuses sandbox + live Payment API keys, registers a project-scoped invoice webhook endpoint, and derives your callback URL from the System URL you typed:

```
https://billing.example.com/modules/gateways/callback/paymosgateway.php
```

### Step 3: Upload to WHMCS (≈40 sec)

Extract the ZIP into your WHMCS root so the following paths exist:

```
modules/gateways/paymosgateway.php
modules/gateways/callback/paymosgateway.php
modules/gateways/paymosgateway/paymos-config.php
modules/gateways/paymosgateway/src/Autoloader.php
includes/hooks/paymosgateway_reconcile.php
```

`paymos-config.php` is **read-only configuration generated by Paymos**. Do not edit it. If you rotate keys, change project, or change the WHMCS System URL — re-download a fresh package from [paymos.io/dashboard/cms](https://paymos.io/dashboard/cms) and re-upload.

### Step 4: Activate and test (≈30 sec)

1. WHMCS admin → **Configuration → Apps & Integrations** (or **System Settings → Payment Gateways** on WHMCS 8.x).
2. Activate **Paymos**.
3. Open Paymos gateway settings → set **Mode: Sandbox** → **Save Changes**.
4. Open a test WHMCS invoice in the client area.
5. Select **Paymos** as the payment method → click the Paymos button.
6. On the hosted Paymos page, click **Simulate payment**.
7. WHMCS invoice should flip to `Paid` within ~5 seconds.

Working? Switch to **Mode: Live**. Done.

## Requirements

- WHMCS **8.13+** or **9.0**
- PHP version supported by your WHMCS release. Do not infer the PHP floor from this module: WHMCS 8.13 adds PHP 8.3 support, and WHMCS 9.0+ requires PHP 8.2+.
- A public HTTPS WHMCS System URL
- An active Paymos account with a project

No Composer install required on your WHMCS server. The package ships with the Paymos PHP SDK bundled.

## Runtime flow

1. Customer opens an invoice in the WHMCS client area, picks **Paymos**.
2. Plugin creates a Paymos invoice via the Merchant API using the WHMCS invoice total and currency.
3. Customer is redirected to the hosted Paymos page.
4. Customer pays in USDT or USDC across major EVM chains; USDT additionally settles on Tron and TON.
5. Paymos confirms the on-chain payment — small payments clear in seconds, larger ones wait for more confirmations.
6. Paymos sends a signed callback to your WHMCS server.
7. Plugin verifies signature + timestamp + amount, then reverse-verifies the terminal state against the Paymos API.
8. WHMCS marks the invoice paid.

If the callback is lost in transit, a WHMCS cron hook polls Paymos every 10 minutes for unresolved invoices.

Reference: [paymos.io/docs/payment-flow](https://paymos.io/docs/payment-flow).

## Configuration

The package pre-fills everything technical. WHMCS admin only exposes presentation choices:

| Setting | What it controls |
|---|---|
| Mode | `Sandbox` for tests, `Live` for production. Switch without re-uploading. |
| Button Text | Label on the Paymos payment button. |

Generated values loaded from `modules/gateways/paymosgateway/paymos-config.php`, not editable in WHMCS:

| Generated value | Description |
|---|---|
| API Key | Sandbox and live Payment keys |
| API Secret | HMAC signing secrets |
| Project ID | Paymos project used for WHMCS invoices |
| Webhook Secret | Sandbox and live callback verification secrets |
| Base URL | Defaults to `https://api.paymos.io` |

To rotate any of these — download a fresh package and re-upload. The previous secret stays valid through a grace window so in-flight callbacks don't fail.

## Webhooks (callback) — pre-registered, no setup

The dashboard registers your callback URL against your WHMCS System URL **before the ZIP is generated**. The callback path is fixed:

```
https://your-whmcs.example.com/modules/gateways/callback/paymosgateway.php
```

You will not need to set this up yourself. The signing secret lives in `paymos-config.php`.

Manage and replay events at [paymos.io/dashboard/developers/webhooks](https://paymos.io/dashboard/developers/webhooks).

Plugin verifies every incoming callback:

- **Signature** — header `X-Webhook-Signature`, format `t={timestamp},v1={hex}`, algorithm HMAC-SHA256, timing-safe compare, ±5 min timestamp tolerance (parsed from the `t=` component, rejects replays).
- **Event ID deduplication** — same `event_id` cannot mark the same invoice paid twice.
- **Reverse verification** — pulls the live invoice from the Paymos API and confirms terminal state before adding a WHMCS payment.

Any check fails → HTTP 4xx response → invoice is **not** marked paid.

Retry policy on the Paymos side: **11 attempts** with exponential backoff over ~32 hours (1m, 2m, 4m, 8m, 16m, 32m, 1h, 2h, 4h, 8h, 16h). Failed callbacks land in the dashboard for manual replay.

Signature verification deep-dive: [paymos.io/docs/webhooks/verify](https://paymos.io/docs/webhooks/verify).
Retry schedule: [paymos.io/docs/webhooks/retry](https://paymos.io/docs/webhooks/retry).

## Reconciliation

A WHMCS cron hook (`includes/hooks/paymosgateway_reconcile.php`) runs every 10 minutes and polls Paymos for any recent unpaid invoices. If a callback was missed in transit, the invoice catches up automatically.

You can also replay any event from [paymos.io/dashboard/developers/webhooks](https://paymos.io/dashboard/developers/webhooks).

WHMCS cron must be running for reconciliation to work. Most managed WHMCS hosts run it on a 5-minute schedule by default.

## FAQ

**Why does the package have everything pre-configured?**
Because the dashboard generates it that way. At download time, the server reads your merchant record, creates Sandbox and Live credentials if missing, derives the callback URL from the WHMCS System URL you typed, registers it on the Paymos side, and writes everything into `paymos-config.php` before zipping. You get a turn-key bundle.

**Do I ever need to paste an API key into WHMCS?**
No. WHMCS gateway settings never ask for one — they only expose the mode switch and the payment button text.

**What if I change my WHMCS System URL?**
Re-download the package from [paymos.io/dashboard/cms](https://paymos.io/dashboard/cms) after updating the URL in the dashboard. The new ZIP carries the updated callback URL and an updated `paymos-config.php`. Re-upload.

**Does this plugin work with WHMCS automated recurring invoices?**
Yes. The gateway is wired into the WHMCS payment flow that recurring invoices already use. Customer pays the recurring invoice the same way as any other.

**What happens if a customer pays late?**
Paymos rejects the on-chain transaction at the domain boundary. The WHMCS invoice stays unpaid, the customer can retry.

**Are there chargebacks?**
No. Crypto settlement is final on confirmation.

**What if the callback never arrives?**
The cron hook polls Paymos every 10 minutes for unresolved invoices. WHMCS invoices catch up automatically. You can also replay any event from [paymos.io/dashboard/developers/webhooks](https://paymos.io/dashboard/developers/webhooks).

**Does this work on WHMCS 7.x?**
No. Minimum is WHMCS 8.13 — the module relies on the modern gateway API.

**Refunds?**
Not exposed in the module yet. Process refunds in the Paymos dashboard.

## Troubleshooting

| Symptom | What to check |
|---|---|
| `Paymos` not appearing under Payment Gateways | WHMCS version below 8.13, or files copied to the wrong directory. Verify the 5 paths under [Upload to WHMCS](#step-3-upload-to-whmcs-40-sec). |
| Gateway settings missing credentials | `paymos-config.php` not present or unreadable. Re-download the package from [paymos.io/dashboard/cms](https://paymos.io/dashboard/cms). |
| Invoice not marked paid after sandbox simulate | WHMCS cron not running, or signature verification failed. Check `Configuration → System Logs` for `paymos` entries. |
| `Signature verification failed` in logs | Package and dashboard configs out of sync. Re-download the package and re-upload. |
| Callback returns 4xx | Webhook secret rotated on dashboard side but old package still installed. Re-download. |
| Live mode shows sandbox banner | Mode switch in WHMCS admin still on Sandbox. |

Error reference: [paymos.io/docs/errors](https://paymos.io/docs/errors).
